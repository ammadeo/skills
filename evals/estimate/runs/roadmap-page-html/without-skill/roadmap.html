Q1 candidates and estimates

Four candidates, 18–34 engineer-days in total. The numbers are effort for one engineer who knows the codebase, including review and testing. They are not calendar time. They were made from one-line descriptions, without reading the code, so each estimate lists what it assumes and what would change it.

The candidates

Dark mode for the dashboard

2–4 days Small Confidence: high

What the work is

  • A dark set of values for the existing colour variables.
  • A theme switch that follows the system setting by default and remembers a manual choice.
  • A pass over every dashboard screen for things the variables do not reach: charts, images, shadows, embedded widgets.
  • A contrast check on text and controls.

Assumes

  • "All colours come from CSS variables" holds in practice, with few stragglers.
  • Dashboard only. Emails and any marketing pages stay as they are.

Would change the estimate

  • Chart colours set in JavaScript instead of through the variables.
  • Hard-coded colours in inline styles or SVG files.
  • No dark palette chosen yet, so someone has to design one (+1–2 days).

Move file uploads to S3

8–15 days Large Confidence: low to medium

What the work is

  • New uploads go to S3.
  • Files are served from S3 with the same access rules as today.
  • A migration script for the roughly 40k existing files: copy, verify, update references, safe to stop and resume.
  • A cutover where the app can still read from the old location until the migration is verified.
  • Bucket setup, permissions and backups, then removing the old storage.

Assumes

  • File locations are stored in one place in the database.
  • The move should happen without downtime.
  • Copying 40k files is the easy part and runs in hours. The effort is in the cutover and in not losing a file.

Would change the estimate

  • File URLs saved inside content or already sent in emails, so old links must keep working.
  • Thumbnails, resizing or scanning that depend on the local disk.
  • A very large total size, in the hundreds of gigabytes.
  • Rules about which region the data may live in.

"Duplicate project" in the project menu

2–5 days Small to medium Confidence: medium

What the work is

  • The menu item, and a name for the copy ("Copy of …").
  • A server-side copy of the project and everything in it, done as one all-or-nothing operation.
  • A permission check: who is allowed to duplicate.
  • Tests for each kind of content a project can hold.

Assumes

  • A project is a moderate number of records, small enough to copy while the user waits.
  • Settings and structure are copied. Comments and activity history are not.

Would change the estimate

  • Projects with attached files: copy them or share them? This ties into the S3 move.
  • Very large projects that need a background job, which the app does not have yet.
  • Integrations, webhooks or share links that must not be copied blindly.

Weekly email digest of project activity

6–10 days Medium Confidence: medium

What the work is

  • Scheduled jobs, which the app does not have yet: a scheduler, retries and alerts when a run fails. About 2–4 days of the total, and reusable afterwards.
  • The digest itself: what happened in each person's projects over the last week.
  • The email, in HTML and plain text.
  • An opt-out setting and an unsubscribe link.
  • Safeguards: never send twice, skip weeks with no activity.

Assumes

  • The app already sends email of some kind.
  • Project activity is already recorded somewhere it can be queried.
  • One send time for everyone.

Would change the estimate

  • No activity log yet (+3–5 days), and the digest only has data from the day recording starts.
  • No email provider set up (+1–2 days).
  • Delivery in each person's own time zone.

Suggested order

  1. Dark mode. Small and self-contained. It can ship first.
  2. S3 move. Start early. It is the largest item and the least certain, and the cutover is better done with slack than at the end of the quarter.
  3. Duplicate project. After the S3 move if projects hold files, so the file copy is written once.
  4. Weekly digest. Independent of the rest. It can run alongside the S3 move if a second engineer is free.

Questions that would tighten the estimates

  • Dark mode: do charts and third-party components take their colours from the variables too? Is there a dark palette already?
  • S3 move: how are files referenced, a database column or URLs inside saved content? What is the total size? Is anything done to a file on upload?
  • Duplicate project: what does a project contain, and what should the copy include: files, members, comments?
  • Weekly digest: is project activity already logged? Does the app already send email?
Drafted 26 November 2026. Estimates are ranges, not commitments. Expect them to narrow once the questions above are answered.
